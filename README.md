# Prompt-Tool Delta Embedding Mismatch Detection

## 한국어 안내

### 1. 저장소 개요

이 저장소는 LLM 에이전트가 사용자 의도와 의미적으로 맞지 않는 도구를 호출하는 상황을 탐지하기 위한 논문 실험 자료를 공개하기 위해 구성되었습니다. 핵심 아이디어는 사용자 프롬프트와 호출된 도구 이름을 각각 문장 임베딩으로 변환한 뒤, 두 임베딩 벡터의 차이(delta vector)를 경량 기계학습 모델의 입력 특징으로 사용하여 정상 도구 호출과 불일치 도구 호출을 분류하는 것입니다.

이 저장소에는 다음 자료가 포함됩니다.

- 데이터셋 생성 및 샘플링 스크립트
- 실험 재현용 Jupyter notebook
- 논문 figure 생성용 notebook
- 실험 결과 표와 메타데이터
- 논문에 사용할 수 있는 figure 파일

대용량 CSV 데이터셋과 저장된 실험 산출물은 Git 저장소에 직접 포함하지 않고, GitHub Release asset으로 제공합니다.

### 2. 라벨 의미

데이터셋의 라벨은 다음과 같습니다.

```text
label = 0: Normal prompt-tool pair
label = 1: Mismatch prompt-tool pair
```

`label = 0`은 ToolBench 데이터에서 관찰된 정상적인 사용자 프롬프트-도구 호출 쌍입니다.

`label = 1`은 같은 사용자 프롬프트에 대해 원래 관찰된 정상 도구를 제외하고, ToolBench에서 관찰된 다른 도구를 결합하여 만든 불일치 쌍입니다. 따라서 `label = 1`은 특정 도구 자체가 악성이라는 뜻이 아니라, 해당 사용자 프롬프트의 문맥에서 호출된 도구가 의미적으로 맞지 않는 경우를 의미합니다.

### 5. 실험 재현 방법

전체 비율 실험을 다시 실행하려면 다음 노트북을 사용합니다.

```text
notebooks/01_toolbench_mismatch_ratio_study_experiment.ipynb
```

이 노트북은 다음 과정을 수행합니다.

- ToolBench 기반 normal/mismatch 데이터셋 로드
- 사용자 프롬프트와 도구 이름 임베딩 생성
- prompt embedding과 tool embedding의 delta vector 생성
- `source_prompt_hash` 기반 group split 적용
- LightGBM, XGBoost, Random Forest, Isolation Forest 학습 및 평가
- Normal:Mismatch 비율별 성능 비교

이미 실행된 결과를 기반으로 논문용 그래프를 다시 생성하려면 다음 노트북을 사용합니다.

이 노트북은 `outputs/runs/paper_ratio_study_results/`에 포함된 저장된 결과 파일을 읽어서 AUROC, AUPRC, F1-score, Recall, ROC/PR curve, latency figure 등을 다시 생성합니다. 전체 실험을 다시 돌리지 않고 figure만 재생성하고 싶을 때 사용하면 됩니다.

이 데이터셋은 ToolBench 기반 데이터에서 파생된 실험용 데이터셋입니다. 공개용 파일에서는 이메일과 URL span을 `[EMAIL]`, `[URL]`로 마스킹했습니다. 또한 품질이 낮거나 실험 shortcut이 될 수 있는 일부 tool name pattern은 데이터 생성 과정에서 제외했습니다.

본 실험의 mismatch pair는 비교적 명확한 프롬프트-도구 불일치 상황을 평가합니다. 예를 들어, 향후 연구에서는 “이메일 열기”와 “이메일 삭제”처럼 더 미묘한 도구 의도 차이를 갖는 세분화된 mismatch 조건을 추가로 평가할 수 있습니다.

## English Guide

### 1. Repository Overview

This repository provides the public release materials for a paper experiment on detecting semantically mismatched tool calls in LLM agents. The core idea is to embed the user prompt and the called tool name separately, compute their delta vector, and use this lightweight feature to classify normal and mismatched tool-call pairs.

The repository includes:

- dataset construction and sampling scripts
- reproducible Jupyter notebooks
- paper figure generation notebooks
- experiment result tables and metadata
- paper-ready figure files

Large CSV datasets and saved run artifacts are not tracked directly in the Git repository. They are distributed separately as a GitHub Release asset.

### 2. Label Definition

The dataset labels are defined as follows.

```text
label = 0: Normal prompt-tool pair
label = 1: Mismatch prompt-tool pair
```

`label = 0` corresponds to an observed successful prompt-tool pair from ToolBench.

`label = 1` is generated by pairing the same user prompt with a different observed ToolBench tool while excluding the normal tools originally observed for that prompt. Therefore, `label = 1` does not mean that the tool itself is malicious. It means that the called tool is semantically mismatched with the given user prompt.

### 3. Downloading the Data Asset

If you clone or download this repository, the code and figures are included, but the large dataset files are not included directly. To run the experiments, download the following file from the GitHub Releases page.

```text
paper-data-v1.0.zip
```

Unzip this file at the repository root.

After extraction, the following paths should exist.

```text
data/datasets/toolbench_mismatch_dataset.csv
data/datasets/ratio_samples/ratio_sample_1_1.csv
data/datasets/ratio_samples/ratio_sample_7_3.csv
data/datasets/ratio_samples/ratio_sample_8_2.csv
data/datasets/ratio_samples/ratio_sample_10_1.csv
data/datasets/ratio_samples/ratio_sample_100_1.csv
outputs/runs/paper_ratio_study_results/
```

The notebooks use repository-relative paths, so no notebook path editing is required if the asset is extracted at the repository root.

### 4. Environment Setup

Create a Python environment and install the required packages.

```bash
pip install -r requirements.txt
```

Jupyter Notebook or JupyterLab is recommended.

```bash
jupyter notebook
```

or:

```bash
jupyter lab
```

### 5. Reproducing the Experiments

To rerun the full ratio study, use:

```text
notebooks/01_toolbench_mismatch_ratio_study_experiment.ipynb
```

This notebook performs the following steps:

- load the ToolBench-derived normal/mismatch dataset
- generate embeddings for user prompts and tool names
- compute delta vectors between prompt embeddings and tool embeddings
- apply a group split based on `source_prompt_hash`
- train and evaluate LightGBM, XGBoost, Random Forest, and Isolation Forest
- compare performance across Normal:Mismatch ratios

To regenerate paper figures from the saved results, use:

```text
notebooks/02_toolbench_mismatch_result_visualization.ipynb
```

This notebook reads the saved artifacts under `outputs/runs/paper_ratio_study_results/` and regenerates AUROC, AUPRC, F1-score, Recall, ROC/PR curve, and latency figures. Use this notebook when you want to regenerate figures without rerunning the full experiment.

### 6. Rebuilding the Dataset From Raw JSON

To rebuild the dataset from raw ToolBench JSON files, place the raw files under:

```text
data/raw/toolbench/G1_answer/
```

Then run:

```bash
python scripts/build_toolbench_mismatch_dataset.py
```

This script builds the full normal/mismatch dataset. The ratio-specific samples used in the paper are included in the GitHub Release asset under `data/datasets/ratio_samples/`.

```text

data/experiment_metadata/   Ratio sampling and split summaries.
docs/                       Dataset card, reproducibility notes, and file manifest.

outputs/runs/               Saved run artifacts. Created after extracting the Release asset.
```

### 8. Notes on the Released Dataset

This dataset is derived from ToolBench. In the public files, email and URL spans are masked as `[EMAIL]` and `[URL]`. Some low-quality or shortcut-prone tool name patterns were filtered during dataset construction.

The mismatch pairs in this experiment evaluate relatively clear prompt-tool semantic mismatches. Future work may extend the evaluation to more fine-grained mismatch conditions, such as the difference between opening an email and deleting an email.
